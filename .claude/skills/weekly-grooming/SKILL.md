---
name: weekly-grooming
description: Weekly review of the GitHub issues for this project. Use when I say "groom the backlog" or "weekly grooming".
---
1. Read memory/goals.md for this quarter's goals. If it has no goals filled in, ask me for them and stop.
2. List the open issues in this repository with their labels, parent and blocked-by links.
3. List parent issues whose children are all closed. Propose closing them.
4. For each open issue without the "ready" label, say in one line what it is missing: what to change, why, a done-when checklist, or limits.
5. Propose up to five issues to hand over next: ready, not blocked, no open children, and linked to a goal. Say which goal each serves.
6. Check that at least one open issue improves the harness (instructions, skills, checks). If none does, propose one.
7. Do not change labels, close issues or start work until I approve each change.
8. Write a session log in memory/sessions/, following memory/sessions/README.md, with what was proposed and what I approved, and add it to memory/MEMORY.md.
